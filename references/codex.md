# Codex에서 실행할 때 (insane-review)

SKILL.md 절차는 그대로 따르고, 아래 차이만 적용한다.

## 선택지 질문 = 질문 도구 (이번 세션 도구 목록으로 판단)

1. `request_user_input_async`가 있으면 질문 1콜 = 이 도구 1콜(문항 ≤4개).
   - 형식: `{"questions":[{"title":"헤더 — 한 줄 질문","options":["추천안 (추천) — 설명","대안 — 설명"]}]}`
   - 문항에는 `title`·`options`만. `question`·`header`·`id`를 넣으면 파싱 오류가 난다.
   - 추천안을 맨 앞에. "기타·직접 적기"는 넣지 않는다(자유 입력 칸이 자동으로 붙는다).
   - 부른 뒤 "위 질문에 답해 주시면 이어서 진행합니다" 한 줄만 쓰고 턴을 끝낸다. 답이 달린 결정을 추측으로 진행하지 않는다.
2. Plan 모드라 `request_user_input`만 있으면: 1콜 3문항까지. `header`(12자 이내)·`id`(snake_case)·`question`, 선택지 2~3개(`label`·`description`), 추천 라벨 끝에 `(Recommended)`.
3. 둘 다 없으면 채팅에 번호 블록(`질문:` + `1. 추천안` `2. 대안` `3. 문장으로 직접 수정 요청`)을 내고 답을 기다린다. "모르면 1번으로 진행"을 덧붙인다.
4. `codex exec`처럼 사람이 답할 수 없는 실행이면 묻지 않는다. 온보딩이 사람 손(로그인 등)을 요구하면 그 단계에서 멈추고 필요한 것을 보고한다.

## 경로와 도구

- `${CLAUDE_PLUGIN_ROOT}`는 이 플러그인 루트(SKILL.md에서 두 단계 위 폴더)로 바꿔 쓴다. 스크립트는 `python3 <루트>/bin/pack_and_ask.py`.
- 첫 실행 설정(`setup/setup.sh`)은 Claude Code 전용이다. Codex에서는 실행하지 않는다(실행해도 아무것도 하지 않는다). 파이썬 의존성은 온보딩의 `deps=missing` 분기(`--check-env --install`)로 채운다.
- 추론 강도는 Claude Code와 같다: 미지정이면 `--effort pro`, 사용자가 명시하면 그 값을 그대로 `--effort`로 넘긴다.
- ChatGPT 웹 브릿지(CDP 9222)는 사용자의 구독 세션과 전용 브라우저 프로필이 필요하다. 로그인은 자동화할 수 없으니 사람에게 요청한다.
- 다른 스킬 호출·서브에이전트가 필요한 단계는 이 스킬에 없다.
